# GPT 生图大师 · astrbot_plugin_gpt_image_studio

在群里让管理员调用 **codex/gpt-image-2** 生图 / 改图，并可用多模态模型对参考图给出 **文字版 PS / Adobe Camera Raw 修图建议**。核心能力：

- **引用图生图**：引用群里的图片（可多张），再发提示词，让模型以这些图为参考改图、融合、换画风。
- **一条消息多张图**：直接跟图发指令，本条消息里的**所有图片**都会被识别为参考图（最多 6 张）。
- **引用消息多张图**：被引用的那条消息里有多张图时，**全部识别**（按内容去重，不会重复灌同一张）。
- **纯文生图**：不发图，直接描述即可。
- **文字修图诊断**：调用现有多模态模型看图，按曝光、白平衡、曲线、HSL、蒙版、锐化/降噪给出可执行的参数建议，**不生图、不改图**。
- **画幅/画质**：`竖版 / 横版 / 1:1`、`--质量 高` 等别名，自动映射到接口参数。

## 安装

需要 AstrBot ≥ 4.29.1、Python ≥ 3.11，并且 QQ 侧用 NapCat / OneBot v11（`aiocqhttp`）。

通过 AstrBot WebUI → 插件 → 上传 ZIP 安装；也可以克隆本仓库后把目录放进 `AstrBot/data/plugins/`：

```bash
cd AstrBot/data/plugins
git clone https://github.com/Cnxiaohun/astrbot_plugin_gpt_image_studio
```

然后在插件配置里填 `api.base_url` 与 `api.api_key`（Magpie 网关：`http://127.0.0.1:3425`，模型 `gpt-image-2`）。

Docker 里的 AstrBot 注意 `127.0.0.1` 指容器自己，要换成宿主地址或 `host.docker.internal`。

## 指令

| 指令 | 说明 |
|---|---|
| `/生图 创建 <提示词>` | 纯文生图，忽略引用和附件 |
| `/生图 编辑 <提示词>` | 编辑引用消息/本条消息里的图，必须有图 |
| `/生图 风格 <画风>` | 保持主体和构图，转换画风 |
| `/生图 融合 <提示词>` | 使用至少两张参考图融合创作 |
| `/生图 诊断 [修图目标]` | 多模态看图，输出文字版 PS/Camera Raw 修图建议 |
| `/生图 重试` | 复用上次成功任务的提示词、参数与参考图，**再次计费** |
| `/生图 状态` | 查看模型、生图/诊断额度、冷却与任务状态 |
| `/生图 帮助` 或 `/生图` | 查看完整帮助 |

画幅、画质、参考图编号写在提示词前后均可：

```text
/生图 创建 --比例 2:3 --质量 高 一张电影海报，宇航员站在荒漠
/生图 编辑 --参考 1,3 把背景换成海边，人物保持不变
/生图 融合 --比例 3:2 将第1张的人物放到第2张场景
/生图 诊断 --参考 1,3 调成通透自然的人像，保留肤质
```

`--参考 1,3` 按图片在原消息中的顺序编号，保持选择顺序。未知操作、未知参数、缺少参数值、越界编号会报错，不会偷偷当作提示词。

重试快照按用户和会话隔离，仅缓存最近30分钟、最多32个任务、总参考图32MB；过期、缓存淘汰或插件重载后需重新发起。旧 `/改图`、`/画风`、`/重画`、`/生图状态`、`/生图帮助` 保留；旧 `/生图 <提示词>` 请改为明确的“创建/编辑”。

### 修图诊断

```text
引用图片 + /生图 诊断
引用图片 + /生图 诊断 调成通透自然的人像，保留肤质
多图 + /生图 诊断 --参考 1,3 偏冷电影感
```

- 只调用**多模态文本模型**，不调用生图接口，不修改任何图片。
- 输出逐图列出可见问题、Camera Raw 基本面板（曝光 EV、高光/阴影等）、可选曲线坐标、HSL 颜色通道、蒙版/修复/裁切操作路径、锐化/降噪建议、操作顺序与检查标准。
- 所有参数都标注为**建议起点**，不是从图片测出的精确值；JPEG/PNG 的色温/色调按相对 -100..+100 标尺说明，不伪造 EXIF、Kelvin 或直方图。
- 诊断模型默认优先复用当前会话的“图片描述模型”，其次当前对话模型；也可在 `diagnosis.provider_id` 显式选择。选择不改变全局默认模型。
- 诊断每日额度独立（默认每人 30 次），不占用生图额度。

### 参考图来源

规范 `/生图 编辑|风格|融合|诊断` 固定优先取被引用消息里的图，否则取本条消息里的图；不会扫描无关群历史。

旧 `/改图` 入口额外支持来源前缀：

| 前缀 | 含义 |
|---|---|
| `引用` / `quote` | 只取被引用消息里的图 |
| `本图` / `图` | 只取本条消息里的图 |
| `最近` / `历史` | 扫群里最近出现的图（`get_group_msg_history`，需平台支持） |
| 不加 | 默认 `auto`：有引用只取引用图，否则取本条图；不偷偷扫描无关群历史 |

## 权限与限额

- 默认**仅管理员可用**（`access.generate_admin_only`），也可在 `access.admin_user_ids` 填白名单 ID。
- 按用户冷却（`limits.cooldown_seconds`）与每日额度（`limits.max_daily_per_user`）。
- 全局并发上限（`limits.max_concurrency`），已在配置里限制在 1..8。
- 诊断调用有独立的每日额度（`diagnosis.max_daily_per_user`）。

## 设计要点

- **后台任务、原群回发**：生图和诊断会立即返回“已受理/处理中”，再由独立任务完成并回**原始会话**；不会因为 LLM 工具或消息流水线的 30 秒超时被取消，也不会把 A 群的结果发到 B 群。
- **不静默计费重试**：只有 429/5xx/连接建立失败才自动重试；读写超时视为“可能已计费”，直接报错让人工确认，绝不偷偷再扣一次。
- **图片安全校验**：只接受 PNG/JPEG/WebP 单帧图，限制尺寸与 20MB 上限；参考图上传前降采样到长边 ≤ 2048，透明底压白。
- **引用多图读取**：OneBot 直接用 `get_msg` 取被引用消息的所有 image 段并核对群号；无 OneBot 连接时解析 `Reply.chain`。任何一张图失效均在付费调用前报错，绝不静默丢图或降级文生图。
- **命令入口**：高优先级 slash 过滤器读取当前消息的纯文本段，忽略引用/At/图片占位，在 `wake_prefix=[]` 时也能接住 `/改图`、`/生图状态`，并阻断后续 LLM 处理。
- **自然语言工具**：注册 `gpt_image_generate` / `gpt_image_edit` / `gpt_image_diagnose`，可被 Agent 工具搜索发现；只返回“任务已受理”，实际工作在后台完成。
- **任务安全**：创建任务前原子占位，同一会话同一用户不会重复提交；不同群可并行；插件停止时取消并等待所有后台任务，不自动重新生成。
- **即时回执**：通过权限/参数检查后、读图和请求模型之前先发“已收到”和任务编号；完成后发结果，失败会明确说明。
- **错误不泄露**：API 错误体不回显远程响应或密钥。
- 生成图落到插件数据目录 `outputs/`，自动只保留最近 200 张。

## 配置项

见 `_conf_schema.json`。主要分组：

- `api`：网关地址、Key、模型、备用模型、超时、extra_body
- `generation`：默认尺寸、质量、参考图模式
- `diagnosis`：诊断多模态模型、超时、输出长度、独立每日额度
- `access`：仅管理员、白名单、回图附带提示词
- `limits`：冷却、每日额度、并发

## 已知限制

- 仅适配 `aiocqhttp`（OneBot v11 / NapCat）；别的平台图片引用解析路径不同，未做适配。
- `gpt-image-2` 主要以提示词控制画幅，`size` 是建议值；插件以接口返回的真实像素为准并如实显示。
- 「最近群图」仅在明确选择 history 时扫描；取不到时会报错，不会换用另一来源的图片。
- 模型是否能正确融合所有参考图需以实际画面为准；成功上传多图不代表模型必定遵循每张图。
- 修图诊断依赖一个声明支持图片输入的模型；如果所选模型不支持图片，诊断会明确报错，不会退化成生图。
